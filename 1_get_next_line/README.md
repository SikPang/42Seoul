# get_next_line

## 1. 프로젝트 설명

파일 디스크립터에서 한 번 호출할 때마다 한 줄을 반환하는 C 함수다. 한 번의 `read`로 읽은 데이터 중 남은 부분을 다음 호출까지 보관하며, 여러 파일을 번갈아 읽을 수 있도록 상태를 관리한다.

<br/>

## 2. 사용 기술 및 학습 범위

**핵심 CS**: 운영체제의 파일 I/O와 버퍼링 — 파일 디스크립터, 읽기 버퍼와 EOF, 호출 간 상태 유지 및 동적 메모리 관리.

- C, POSIX `read`, 파일 디스크립터
- 정적 변수, 동적 메모리, 연결 리스트
- 버퍼링, 개행 탐색, EOF·읽기 오류 처리
- 컴파일 매크로 `BUFFER_SIZE`

<br/>

## 3. 핵심 기술 및 설계

- **FD별 상태 보관**: 정적 `t_list`의 각 노드에 `fd`와 미소비 문자열을 저장한다. 고정 크기 FD 배열 대신 이중 연결 리스트에서 필요한 노드를 찾거나 생성한다.
- **읽기와 반환 분리**: 개행이 나올 때까지 버퍼를 누적한 뒤, 개행을 포함한 앞부분을 반환하고 나머지를 노드에 남긴다.
- **종료 시 정리**: EOF에서 개행 없는 마지막 문자열도 반환한다. 더 읽을 데이터가 없거나 읽기 오류가 발생하면 해당 노드를 제거한다.
- **기본/보너스의 실제 차이**: 현재 저장소의 두 버전은 헤더 이름 등을 제외하면 같은 방식으로 동작하며, 기본 버전도 여러 FD를 관리한다.

반환 문자열은 호출자가 `free`해야 한다. 반환값 `NULL`만으로 EOF와 오류를 구분하는 별도 API는 제공하지 않는다.

구현 근거: [줄 읽기](get_next_line.c), [FD 리스트 관리](get_next_line_utils.c), [보너스](get_next_line_bonus.c), [인터페이스](get_next_line.h).

## 4. 프로그램 실행법

Makefile은 포함하지 않는다. C 컴파일러가 있는 Unix 계열 환경에서 테스트 프로그램과 함께 컴파일한다. 기본 `BUFFER_SIZE`는 42다.

```sh
cd 1_get_next_line
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 -I. \
    test/main.c get_next_line.c get_next_line_utils.c -o gnl_test
cd test
../gnl_test
```

테스트는 현재 작업 디렉터리의 `t_edge.txt`를 열어 정해진 횟수만큼 호출한다. 다른 파일은 `test/main.c`의 `open` 대상과 호출 부분을 바꿔 확인한다.

보너스 버전은 프로젝트 폴더에서 아래처럼 별도로 빌드한다.

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 -I. \
    test/main.c get_next_line_bonus.c get_next_line_utils_bonus.c -o gnl_bonus_test
cd test
../gnl_bonus_test
```

기본과 보너스는 같은 함수 이름을 정의하므로 하나의 실행 파일에 동시에 링크하지 않는다.

<br/>

## 5. 구현 범위

### 구현된 기능

- 호출당 한 줄 반환, 개행이 있으면 반환 문자열에 포함
- 읽은 데이터의 잔여 부분 보관
- 개행 없는 마지막 줄과 빈 파일 처리
- FD별 노드 검색·생성·삭제와 여러 FD의 교차 읽기
- EOF·읽기 오류 시 해당 상태 해제
- 컴파일 시 버퍼 크기 변경
- 빈 파일·개행·한 줄·경계 입력 샘플 및 테스트 코드


### 사용 시 제약

- 정적 리스트를 공유하므로 스레드 안전성을 제공하지 않는다.
- EOF까지 읽기 전에 FD를 닫는 경우를 위한 별도 상태 정리 함수는 없다.
- FD 재사용과 메모리 할당 실패의 모든 경로를 보장하는 테스트는 포함하지 않는다.
